# Подготовка развёртывания готового образа

Пакет: `ghcr.io/twistyskrill/devops-ci-app`, публичный; для чтения не нужен PAT.

Проверенный исходный коммит после восстановления точки входа: `9b6ac71701ce04a6a5449ebef42a7b08a347135e`. После следующих публикаций выбирайте конкретный прошедший CI SHA или digest из журнала Push image и фиксируйте его в inventory.

Для учебной проверки вне CI используется установленный Docker Desktop на Windows с Linux engine. Контейнер слушает 5000/tcp, health endpoint: `/health`, ожидается HTTP 200 и JSON `{"status":"ok"}`; пользователь образа: `app`. Локальная публикация: `127.0.0.1:5001:5000` (latest) и `127.0.0.1:5002:5000` (SHA).

Для Ansible нужны адрес выбранной VM, существующий SSH-пользователь и путь к ключу в локальной конфигурации доступа, имя образа с выбранным SHA/digest, имя контейнера, host/container ports и health endpoint. Адрес VM и секреты в этот публичный репозиторий не включаются. Inventory задаётся для реально выбранного узла перед деплоем.

Playbook должен загрузить готовый образ, привести контейнер к заданному состоянию и проверить health. Повторный запуск с тем же образом и настройками должен быть идемпотентным. Task описывает действие, handler выполняется по уведомлению об изменении, role группирует переиспользуемые задачи и переменные. Повторная сборка на каждой VM не нужна: она могла бы получить другой базовый образ или зависимости и расходует ресурсы.

Для точного закрепления используйте `ghcr.io/twistyskrill/devops-ci-app@sha256:<digest>` из проверенной публикации. SHA-тег связывает образ с исходным коммитом, latest остаётся перемещаемым указателем.
